Ghar 2.5 — Android, iPhone and GitHub Pages

This package adds a complete installable web app (PWA) with the existing budget UI. It does not contain an Android APK or iOS IPA. Share the hosted app link; family members install it on their home screens and sign in with Google. The owner completes the Google setup below once.

What runs where

PartRuns on
Purple budget UI, installation files and iconsGitHub Pages, from github-pages/
Login consent and OAuthGoogle Identity Services
Validation, membership, row revisions and savingExisting Google Apps Script project, deployed as an API executable
Family budgets, expenses, transfers, meters and membersYour connected Google Sheet

GitHub Pages serves static files; uploading .gs files does not run Apps Script. The phone UI calls the authenticated Google Apps Script API. It does not embed the Google app in a WebView or iframe. Your current Google web app can continue to run alongside the phone version. Both use the same script project and database.

For an existing installation, follow UPGRADE-2.5.html in the ZIP. Version 2.5 adds change logs and a recycle bin without changing the two OAuth scopes or public IDs. Update the same API deployment to a New version and keep your working app-config.js values.

1. Publish the phone UI

  1. Create a GitHub repository, for example GharBudget.
  2. Upload the contents of github-pages/ to the repository root. Include the icons folder and .nojekyll file. index.html must be at the root.
  3. In the repository, choose Settings → Pages → Deploy from a branch → main → /(root) → Save.
  4. Wait for the Pages deployment, then copy its HTTPS URL. The expected project-site shape is https://YOUR-USERNAME.github.io/GharBudget/; use the actual URL GitHub gives you.

Do not upload a household spreadsheet, exported family backup, access tokens or client secrets. Public application code and the two public IDs below are sufficient. A public UI does not grant access to family data; Google file access and app membership are checked on the server.

2. Connect the existing Apps Script project to Google Cloud

  1. Keep your current Google Sheet and Apps Script project. Update its Code.gs, HTML file Index, and appsscript.json with this package. Do not repeat family setup.
  2. In Google Cloud Console, create/select a standard Cloud project. Enable Google Apps Script API. In Apps Script Project Settings → Google Cloud Platform project, associate that same project's project number.
  3. Configure the Cloud project's Google Auth Platform/OAuth consent screen. For a family using personal Gmail accounts, use an External audience. While the app is in Testing, add every family Google email as a test user. Publishing broadly can require Google's OAuth verification; a ZIP cannot pre-authorize that.
  4. Add the two scopes used by this supplied script:
  5. https://www.googleapis.com/auth/spreadsheets
  6. https://www.googleapis.com/auth/userinfo.email
  7. Create an OAuth Web application client in the same Cloud project. Under Authorized JavaScript origins, add your exact site origin, for example https://YOUR-USERNAME.github.io. Do not append the repository path. Add a custom-domain origin separately if you use one.
  8. Copy its client ID ending in .apps.googleusercontent.com. This browser token flow does not use a client secret. Do not put a secret in the repository.

Switching Cloud projects can require existing users to authorize the script again. Follow your Google/Workspace policies. The owner's Cloud project and OAuth configuration cannot be created by extracting this ZIP.

3. Add an API executable deployment

  1. In Apps Script, choose Deploy → New deployment → Select type → API executable.
  2. Allow the Google accounts that will use the app. The supplied manifest uses executionApi.access: ANYONE, meaning logged-in Google users; each request still needs its own OAuth token, sheet access and active Ghar membership.
  3. Deploy and copy the API executable deployment ID from Deploy → Manage deployments.
  4. This is not the spreadsheet ID, the script project ID, or the web-app /exec URL. The phone client calls https://script.googleapis.com/v1/scripts/DEPLOYMENT_ID:run with function: api, using the deployed version (devMode: false).

Keep your existing Web app deployment if you want its /exec link to continue working. Update that deployment to the new version too. The API executable is an additional entry point, not a replacement sheet or family.

4. Fill the two public IDs

Edit app-config.js in the GitHub repository:

window.GHAR_CONFIG={
  clientId:'YOUR_WEB_CLIENT_ID.apps.googleusercontent.com',
  deploymentId:'YOUR_API_EXECUTABLE_DEPLOYMENT_ID'
};

Commit the change. Open the Pages URL and select Continue with Google. Both IDs must belong to the same standard Cloud project as the script. Family members do not edit this file or deploy their own script.

5. Connect the family and install

  1. Sign in with your existing family Google account. Its connection preference is retained in the same script project. If needed, use Connect an existing sheet to reconnect your current Ghar spreadsheet.
  2. For a new family, create a sheet or import an existing supported workbook once. Ongoing monthly sync remains removed.
  3. In Settings, add family Google emails and grant spreadsheet edit access. Use Share family link to copy the phone-app join URL.
  4. Android: open the shared link in Chrome → Install app, or browser menu → Add to Home screen/Install.
  5. iPhone: open the link in Safari → Share → Add to Home Screen → Open as Web App if offered → Add.
  6. Open the Ghar icon and sign in with the listed Google account. Use Safari/Chrome rather than WhatsApp's embedded browser for sign-in and installation.

Each account needs Google file access and active app membership. Google may ask the user to approve scopes. The web token lasts for a limited time and is held only in memory; after reopening or expiry, tap Continue with Google again. A refresh button, error-form button and Settings option are available. Unsaved forms are retained when reauthorizing the same account; switching accounts closes the old editor.

Offline behavior and updates

Only public UI files and icons are cached for launch. Household rows and Google responses are not stored in the service-worker cache. Loading/saving live family data needs internet. Offline edits are not queued. If a network error makes a save result uncertain, refresh first to check whether it completed before retrying. New-row request IDs and row revisions remain enforced by the backend.

After uploading new UI files, close/reopen the installed app or use Settings → Check app update. Close edit forms before applying an update. For server changes, update the API executable deployment to New version while retaining its ID. Merely saving source in the script editor does not update the deployed API version.

Verify with two family accounts

  • Sign in, reconnect the existing family and verify its totals.
  • Add a small plan/expense from the installed app; verify its row in the Ghar database table. Edit it directly in Sheets, then refresh the phone app.
  • Record Payment on Plan, Extras and Total; verify repayments affect Total once.
  • Save a meter reading timestamp with seconds and a floor override; reopen it on the other phone.
  • Verify a second listed account can join and an unlisted account cannot read this family.
  • Check loaders, expired-session recovery, offline errors and installation on a physical Android and iPhone.

Live OAuth, Google policy, API deployment and physical-device installation cannot be verified without your accounts/devices. The included tests use mocked Google services and API responses.

If you specifically need APK and IPA files

An Android APK is a separate signed native build that can be distributed outside Google Play. A native iOS app requires Apple signing and distribution, such as TestFlight/App Store, or an ad hoc build for registered devices. An arbitrary shared IPA does not install on every family iPhone. No native binary or signing credential is included here. The PWA is the supported cross-platform installation in this package.
